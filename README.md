# retron

옛날 DOS 게임, 슈퍼패미컴(SFC), 게임보이 어드밴스(GBA), 닌텐도 DS(NDS) 게임을 브라우저에서 하는 웹 런처입니다. 여러 게임을 등록해 두고 라이브러리에서 골라 플레이합니다.

> 게임 파일은 이 저장소에 들어 있지 않습니다. 본인이 가진 게임 파일을 직접 등록해서 씁니다. 등록한 게임은 브라우저 저장소(OPFS)에 두고, 로그인하면 본인 구글 드라이브에만 올라갑니다. 다른 사용자와 공유되지 않습니다.

## 기능

- **라이브러리**: 등록한 게임을 그리드나 목록으로 봅니다. 썸네일은 게임 아이콘(.ico)이 있으면 그것을, 없으면 첫 실행 화면을 1:1로 잘라 씁니다.
- **휴대폰·태블릿은 앱(PWA)으로만**: 브라우저 탭으로 열면 설치 화면만 나옵니다 (안드로이드: 앱 설치 버튼, 아이폰: 사파리 공유 → 홈 화면에 추가). 설치한 앱은 전체 화면으로 열리고, 브라우저가 저장 공간을 비울 때 게임 파일을 지우지 않습니다. PC는 브라우저 그대로 씁니다. 아이폰은 설치한 앱이 사파리와 저장 공간을 따로 써서, 앱에서 다시 로그인하고 게임은 드라이브에서 받습니다
- **게임 등록**: zip이나 ROM 파일을 고르거나 창에 끌어다 놓습니다. 고른 파일을 드라이브에 이름 그대로(zip은 zip, 롬은 롬) 올리는 것과 이 기기에서 풀어 실행 준비하는 것을 동시에 합니다 ("+ 게임 추가" 버튼 테두리에 진행률 고리, 화면 아래에 "압축 푸는 중 n% · 드라이브 n%"). 다 풀었는데 아직 올리는 중이면 원본을 기기에도 잠시 보관했다가 다 올리면 지웁니다. 지금 못 올리면(오프라인, 모바일 데이터에서 큰 파일) 원본을 보관해 두고 나중에 올립니다. zip 하나에 롬이 여럿이면 롬마다 게임 하나로, 드라이브에도 롬을 하나씩 올립니다. 드라이브에 풀린 파일을 하나씩 올리는 일은 없습니다: 원본이 기기에 없으면(원본을 보관하지 않던 때 추가한 게임, 저장 공간이 모자라 보관하지 못함) 롬은 롬 파일 그대로, DOS는 기기의 게임 폴더를 zip 하나로 묶어(기기에 사본을 만들지 않고) 올립니다.
  - 알려진 게임에 꼭 필요한 파일이 빠져 있으면 추가할 때 알립니다 (창세기전2: `BLACKBOX.DEF`가 없으면 "처음부터 시작"이 "blackbox.def read error!"로 끝납니다. 세이브 `BLACKBOX.SV1~SV5`·`BLACKBOX.DAT`와 이름이 비슷하지만 세이브가 아니라 새 게임 초기 데이터라 지우면 안 됩니다).
  - **DOS**: 실행 파일이 있는 폴더를 C:로 씁니다. bin/cue나 iso가 있으면 D:(CD)로 연결합니다. CD 음악(레드북 오디오)도 재생됩니다.
  - **SFC**: .sfc, .smc, .fig, .swc / **GBA**: .gba / **NDS**: .nds (BIOS·펌웨어 없이 melonDS 내장 BIOS로 바로 시작합니다)
  - **zip**: zip 끝의 파일 목록을 읽고 파일마다 잘라서 스트리밍으로 풉니다. 수백 MB짜리, macOS·iOS에서 압축한 zip, 4GB가 넘는 zip(zip64)도 되고, 한글(CP949) 파일명도 읽습니다.
- **저장**
  - **게임 안 세이브**: 게임에서 저장하면 브라우저에 자동으로 보관됩니다.
  - **상태 저장/불러오기**: 게임마다 슬롯 4개를 씁니다.
  - **자동 저장**: 메뉴(☰)를 열 때, 나가거나 웹을 닫거나 다른 앱으로 넘어갈 때만 저장합니다. 몇 분마다 하는 저장은 하지 않습니다 (멈춘 에뮬레이터는 저장하는 동안 잠깐 풀어야 해서, 메뉴를 열어 둔 채 기다리면 게임이 잠깐씩 진행됐습니다)
- **화면 버튼**: Save·Load(슬롯 팝업을 엽니다), 빨리가기(눌러서 켜고 끕니다), 메뉴(☰).
  - 휴대폰: 왼쪽 위에 Save·Load, 오른쪽 위에 빨리가기·메뉴. 세로 화면은 조작 영역 맨 위(게임 바로 아래), 가로 화면은 화면 맨 위 양끝
  - PC: 화면 오른쪽 아래에 Save·Load / 빨리가기·메뉴 두 묶음으로 흐리게 띄웁니다
- **게임 중 메뉴(☰)**: 열면 게임이 멈춥니다. 게임 중에 다른 창이 덮거나 앱이 뒤로 가면(홈, 다른 앱, 화면 꺼짐) 메뉴가 저절로 열려 멈추고, 돌아와도 메뉴를 닫을 때까지 멈춰 있습니다.
  - 아이콘 여섯: 나가기(자동 저장), 필터(선명, 부드럽게, CRT), 다시 시작(처음부터. 그 전 상태는 자동 저장 슬롯에 남깁니다), 스크린샷(정수배로 키운 PNG로 내려받기), 방향(가로·세로, 휴대폰) 또는 전체화면(PC), 조작
  - SFC·GBA·NDS: 아이콘 아래에 빨리가기 배속(2×, 3×, 4×). SFC·GBA(RetroArch 웹 빌드)는 실행 중에 배속을 못 바꿔서, 지금 상태를 들고 에뮬레이터를 다시 띄웁니다. NDS는 바로 바뀝니다
  - **조작**을 누르면 조작 화면으로 넘어갑니다 (‹로 돌아옴)
    - DOS 휴대폰: 트랙패드 켜기·끄기(게임마다), 키 버튼 고르기(전체 키보드 + 숫자 키패드에서. 방향키나 키패드 8·4·6·2를 켜면 방향 패드로 나옵니다), 마우스 감도(트랙패드·게임패드 커서). PC는 실제 마우스를 쓰므로 없습니다
    - SFC·GBA: PC는 키보드 설정(기본 배치가 있고 기종마다 공통. "패드에서 바꾸기"를 누르면 컨트롤러 그림이 뜨고, 버튼마다 지금 키가 적혀 있다. 버튼을 누른 뒤 쓸 키를 누르면 바뀐다), 휴대폰은 가상패드 켜고 끄기
    - 휴대폰 공통(모든 게임): 방향 조작(원형·십자 패드), 버튼 크기, 버튼 투명도, 햅틱(켜는 순간 한 번 떨어서 되는지 바로 압니다)
    - 게임패드 연결 상태
- **계정 창**(오른쪽 위 동그라미): 동기화 상태, 기기 저장 공간(이 브라우저가 쓰는 양 / 쓸 수 있는 양), 모바일 데이터로 게임 안 올리기(유선·Wi-Fi는 올림. 휴대폰 데이터인지는 안드로이드 크롬만 알려 줍니다), 로그아웃
- **게임 설정(카드의 ⋯)**
  - 이름 변경
  - DOS: 실행 파일, 속도(cycles), 휴대폰 화면 키(휴대폰, 기본 ESC·Enter·Space·방향 패드), 게임패드 버튼 배치(게임패드가 연결돼 있을 때만)
  - 세이브 백업: 게임 안 세이브와 상태 슬롯을 zip으로 내보내고 가져옵니다.
  - SFC·GBA(PC): 키보드 설정 (게임 중 메뉴와 같은 컨트롤러 그림 팝업. 그 기종 게임 모두에 적용)
  - 정보: 구글 드라이브에 올라가 있는지(이 기기에만 있으면 바로 올리기), 저장 공간, 추가한 날, 마지막 플레이
  - 삭제: **이 기기에서 삭제**(드라이브에 있으면 "다운로드 필요" 카드로 남습니다) / **드라이브에서도 삭제**(다른 기기 라이브러리에서도 사라집니다. 세이브는 드라이브에 남깁니다)
- **당겨서 새로고침**(휴대폰): 라이브러리 맨 위에서 아래로 쓸어내렸다 놓으면 드라이브 게임 목록과 썸네일을 다시 읽습니다
- **라이브러리 카드**: 상태는 둘입니다. **실행 가능**(이 기기에 있음)과 **다운로드 필요**(드라이브에만 있음, 썸네일에 반투명 막). 다운로드 필요 카드를 누르면 받기만 하고, 다 받은 뒤 다시 누르면 실행합니다. 올리기·받기 진행률은 썸네일 아래쪽에 나옵니다
  - 게임 파일이 기기에서 사라졌으면(브라우저가 저장 공간을 비움) 누를 때 드라이브에서 같은 자리로 다시 받습니다. 세이브는 그대로 둡니다
- **조작**
  - PC: DOS는 키보드와 마우스, SFC·GBA는 키보드(메뉴에서 바꿈)
  - 휴대폰 DOS: 방향 패드(방향키), 트랙패드(탭은 왼쪽 클릭, 길게 누르면 오른쪽 클릭), 키 버튼
    - 트랙패드는 화면 방향과 상관없이 방향 패드와 같은 높이입니다
    - 트랙패드·게임패드 스틱은 커서를 이동량으로 보냅니다 (창세기전2 필드처럼 이동량만 읽는 게임도 커서가 움직입니다)
    - 키 버튼이 자리를 넘치면 오른쪽에 스크롤 막대가 생깁니다 (끌거나 누른 자리로 넘어감). 키 위를 끌어서 스크롤하지 않는 것은 키가 닿는 순간 눌려야 해서입니다
    - 왼쪽은 방향, 오른쪽은 버튼으로 배치는 하나입니다 (예전의 트랙패드 위치·가로 배치 설정은 없앴습니다)
    - 세로 화면: 방향 패드·트랙패드 줄, 그 아래 키 버튼 줄을 화면 아래에 붙입니다. 트랙패드를 끄면 방향 패드 오른쪽에 키 버튼
    - 가로 화면: 화면 아래 왼쪽에 방향 패드, 오른쪽에 트랙패드와 그 위에 키 버튼(3칸씩. 트랙패드를 끄면 키 버튼이 그 자리로)
  - NDS 아래 화면은 터치스크린입니다: PC는 마우스로 누르고 끌고, 휴대폰은 손가락으로 (한 손가락)
  - 휴대폰 SFC·GBA·NDS: 가상패드. 세로 화면은 L·R부터 아래를 화면 아래에 붙입니다. 가로 화면은 L·R이 Save·Load / 빨리가기·메뉴 바로 아래에 옵니다. 십자 패드는 가운데를 X자로 나눠 누른 방향의 오각형이 밝아집니다
    - NDS: 세로 화면은 가상패드 자리를 남기고 게임 화면(위아래 두 화면, 2:3)을 줄입니다. 가로 화면은 SELECT·START를 아래 화면 위가 아니라 오른쪽 버튼 위에 둡니다
  - 휴대폰은 노치·홈 막대를 피해서 놓습니다. 화면을 CSS로 돌린 가로 화면(아이폰)에서도 기기의 위아래를 피합니다. 가로 화면은 안전 여백에 12~16px을 더 띄웁니다 (안전 여백에 딱 맞추면 노치 가장자리에 살짝 겹쳤습니다)
  - 게임패드: 꽂고 아무 버튼이나 누르면 바로 씁니다. DOS는 버튼을 키나 마우스 버튼으로, 스틱은 방향키나 마우스 커서로 보냅니다
  - 화면 확대(핀치 줌, 두 번 탭)는 막혀 있습니다

알려진 게임은 맞춤 설정을 씁니다(`src/platforms/dos/profiles.ts`). 지금은 창세기전2가 들어 있습니다.

## 실행

```bash
npm install
npm run dev
```

`npm run build`를 하면 `dist/`에 정적 파일이 만들어집니다.

### 구글 로그인과 드라이브 저장

Cloudflare Pages는 정적 파일 서빙과 드라이브 토큰 갱신(아래)만 합니다. 로그인하면 게임 파일, 세이브, 설정이 **각 사용자의 구글 드라이브** `retron` 폴더에 저장되고, 다른 기기에서 같은 계정으로 로그인하면 게임을 받아 이어서 할 수 있습니다. 앱은 `drive.file` 권한만 써서, 자기가 만든 파일 외의 드라이브 내용은 보지 못합니다.

**기기 우선(오프라인에서도 됨)**: 게임 파일, 세이브, 설정은 모두 먼저 이 기기에 저장하고, 드라이브에 연결돼 있으면 올립니다. 못 올린 것은 표시해 두었다가 연결되면 올립니다.

- 한 번 로그인한 기기는 계정을 기억해서, 다시 열면 첫 화면(로고 + 로딩)을 잠깐 보여 주고 라이브러리로 들어갑니다. 오프라인이어도 들어갑니다.
- 드라이브 토큰: 갱신 토큰 서버(`functions/api/auth`, Cloudflare Pages Functions)가 있으면, 로그인할 때 페이지째 구글로 다녀오면서 갱신 토큰을 받아 암호화한 쿠키에 두고, 1시간짜리 접근 토큰이 끝나면 창 없이 새로 받습니다. 서버는 아무것도 저장하지 않습니다. 서버를 못 쓰면(개발 서버, 비밀값 없음) 1시간짜리 토큰만 쓰고, 끊기면 로그아웃하지 않고 위쪽에 **드라이브 연결** 버튼을 보여 줍니다.
- 설정은 기기와 드라이브 중 마지막으로 바꾼 쪽을 남깁니다 (`settings.json`의 `updatedAt`).
- 라이브러리는 이 기기의 게임과 드라이브의 게임을 늘 같이 보여 줍니다. 드라이브 목록은 기기에 적어 둬서 오프라인에서도 보입니다. 드라이브에 없는 게임은 연결될 때·화면으로 돌아올 때·5분마다 올립니다 (올렸는지는 게임 설정의 정보에서 봅니다).
- 게임 올리기·받기: 큰 파일은 조각 4개를 동시에 받고, 작은 파일은 여러 개를 동시에 올리고 받습니다. 아이폰 사파리에서 기기 저장소 파일을 그대로 보내면 실패할 때가 있어서 보낼 조각을 메모리로 읽어서 보냅니다.
- 큰 파일 올리기는 이어 올리기 세션을 기기에 적어 둬서, 화면이 꺼지거나 다른 앱으로 가서 끊겨도 끊긴 지점부터 잇습니다. 올리고 받는 동안에는 화면이 꺼지지 않게 합니다(Wake Lock). 웹 페이지는 다른 앱으로 넘어간 동안 실행되지 않아서 그동안 올리기를 계속하지는 못합니다.
- 서비스 워커(`public/sw.js`)가 앱과 에뮬레이터 파일을 기기에 둬서, 네트워크 없이도 앱이 열리고 기기에 있는 게임을 할 수 있습니다. 에뮬레이터는 그 기종 게임을 온라인에서 한 번 실행해야 기기에 남습니다.

```
내 드라이브/retron/
  games/{게임 이름}/ 추가할 때 고른 원본(zip, 롬, 이름 그대로) + manifest.json (게임키는 폴더의 appProperties.key)
                    원본이 기기에 없던 DOS 게임은 게임 폴더(HDD/, CD/)를 묶은 {게임 이름}.zip (받으면 게임 폴더에 그대로 풂)
                    예전 버전이 올린 게임은 폴더 이름이 게임키이고 풀린 파일이 하나씩 들어 있습니다 (받기는 되고, 앱이 지우지 않습니다.
                    같은 게임이 zip 폴더로도 있으면 zip 쪽을 씁니다. 필요 없으면 드라이브에서 직접 지웁니다)
  saves/{게임키}.zip 세이브 묶음 (게임 안 세이브, 상태 슬롯, SRAM)
  settings.json     볼륨, 화면 필터 등
```

- `.env`의 `VITE_GOOGLE_CLIENT_ID`: Google Cloud OAuth 클라이언트 ID (웹 애플리케이션). 승인된 JavaScript 원본에 사이트 주소를 넣어야 합니다.
- `npm run deploy`: 빌드한 뒤 Cloudflare Pages 프로젝트 `retron`에 배포합니다.

#### 갱신 토큰 서버 설정 (한 번)

1. Google Cloud 콘솔 → OAuth 클라이언트 → **승인된 리디렉션 URI**에 `https://retron.pages.dev/api/auth/callback` 추가
2. OAuth 동의 화면의 게시 상태를 **프로덕션**으로 (테스트 상태면 갱신 토큰이 7일 뒤 만료됩니다)
3. Pages 비밀값 세 개: `GOOGLE_CLIENT_ID`(클라이언트 ID), `GOOGLE_CLIENT_SECRET`(클라이언트 보안 비밀), `TOKEN_KEY`(쿠키 암호화 키, `openssl rand -base64 32`)
   ```bash
   npx wrangler pages secret put GOOGLE_CLIENT_SECRET --project-name retron
   ```
4. 다시 배포하면 켜집니다. 셋 중 하나라도 없으면 서버는 꺼져 있고(`/api/auth/config` → `enabled: false`) 앱은 1시간 토큰 방식으로 동작합니다.

로컬에서 서버까지 보려면 `.dev.vars`에 같은 값을 넣고 `npm run build && npx wrangler pages dev dist`를 씁니다 (`npm run dev`에서는 서버를 쓰지 않습니다).

## 참고

- js-dos 8은 CD 오디오 트랙으로 raw BINARY만 재생합니다. 그래서 bin/cue는 등록할 때 `DATA.ISO`와 `TRACKnn.BIN`으로 나눠 둡니다.
- DOS 상태 저장은 DOSBox-X의 savestate(`hand_savestate`/`hand_loadstate` 이벤트)를 씁니다.
- DOS 빨리가기는 DOSBox-X Turbo(`hand_speedlock2` 이벤트)를 켜고 끕니다. 배속은 정할 수 없고 최대 속도입니다.
- DOS 재시작은 js-dos에 리셋이 없어서 에뮬레이터를 새로 띄웁니다.
- 게임 중(화면에 보이는 동안)에는 세이브·상태를 드라이브에 올리지 않고, 나가거나 다른 앱으로 갈 때 올립니다. DOS 에뮬레이터 워커는 메인 스레드와 초당 만 번 가까이 주고받아서, 메인 스레드가 묶기·올리기로 잠깐만 막혀도 게임과 소리가 끊겼습니다. 상태 슬롯은 이미 압축돼 있어서 다시 압축하지 않고 담습니다.
- 휴대폰은 화면이 꺼지거나 다른 앱으로 가면 게임 올리기가 멈추므로, 다시 돌아오면 이어서 올립니다.
- 리퀴드 글래스 글자색: 뒤가 밝으면(게임 화면, 밝은 썸네일) 유리를 밝게·글자를 검게 바꿉니다 (`src/ui/adaptive-contrast.ts`). 브라우저가 요소 뒤 픽셀을 알려 주지 않아서 게임 화면은 작은 격자로 찍어 재고(SFC·GBA는 스크린샷), 썸네일은 한 번 재서 기억합니다.
- 메뉴를 열면 에뮬레이터를 멈춥니다. 멈춘 동안에는 상태 저장 명령이 처리되지 않아서, 저장·불러오기(나갈 때 자동 저장 포함) 동안만 잠깐 풀었다가 다시 멈춥니다 (`src/player/bridge.ts`).
- NDS: RetroArch 웹 빌드(Nostalgist가 쓰는 것)에는 NDS 코어가 없어서 EmulatorJS가 빌드한 melonDS를 씁니다. 이 코어는 RetroArch 명령 대신 자체 함수(`simulate_input`, `save_state_info`, `toggleMainLoop` …)를 내보내서 Nostalgist로 띄울 수 없고 직접 부릅니다. 빌드할 때 `scripts/copy-emulators.mjs`가 7z로 묶인 코어를 받아 풉니다(`7z-wasm`).
  - 코어는 캔버스의 CSS 크기로 다시 그려서, 캔버스 CSS 크기를 코어 해상도(256×384)로 두고 transform으로 키웁니다 (화면 필터가 다른 기종처럼 듣습니다).
  - 터치: 코어는 이벤트 좌표를 캔버스 위치(getBoundingClientRect) 기준으로 재고 devicePixelRatio를 곱해서, CSS로 돌린 화면(아이폰 가로)·키운 화면에서 어긋납니다. 실제 마우스·터치 이벤트는 코어에 닿지 않게 막고, 캔버스 안 좌표로 바꾼 이벤트를 다시 보냅니다(마우스는 마우스로, 손가락은 터치로. 터치 기기에서 코어는 터치만 읽습니다). 한 프레임 안에 떼면 터치를 놓쳐서 50ms는 누른 채로 둡니다.
  - 나갈 때 코어가 단 이벤트 리스너·ResizeObserver를 떼어 코어 메모리를 풉니다 (안 떼면 나간 뒤에도 키를 누를 때마다 죽은 코어를 불렀습니다).
- 버튼 햅틱: 안드로이드는 `navigator.vibrate`(25ms. 12ms는 많은 폰에서 느껴지지 않았습니다), 아이폰은 iOS 18부터 스위치 체크박스의 시스템 햅틱을 빌려 씁니다. 그보다 옛 iOS는 진동이 없습니다. 안드로이드는 손가락이 닿을 때 pointerdown과 touchstart 둘 다에서 부르고 한 번으로 합칩니다 (게임 조작 위에서는 확대를 막으려고 touchstart 기본 동작을 끄는데, 브라우저마다 어느 쪽을 사용자 조작으로 쳐 주는지 달라서 게임 안에서만 진동이 안 났습니다). 아이폰은 손가락을 뗄 때(touchend) 떱니다. 웹킷은 touchstart·pointerdown을 사용자 조작으로 쳐 주지 않아 그때 누른 스위치는 햅틱 없이 바뀌기만 했습니다 (기기 확인 전).
